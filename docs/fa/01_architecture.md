# معماری داخلی و اصول طراحی کتابخانه EDC (EmbeddedDataConvert)

کتابخانه **EDC** یک کتابخانه استاندارد، مستقل و صنعتی به زبان C (استاندارد C99/C11) است که برای تبدیل، اعتبارسنجی، فرمت‌دهی، رمزگذاری و نرمال‌سازی انواع داده‌ها در سیستم‌های نهفته (Embedded Systems) با اولویت **STM32** و **ESP32** طراحی شده است.

---

## ۱. اصول بنیادی طراحی (Core Design Principles)

### ۱.۱. عدم تخصیص پویای حافظه (Zero Dynamic Memory Allocation)
هیچ‌یک از توابع هسته و زیرسیستم‌های EDC از توابع `malloc()`, `free()`, `calloc()` یا `realloc()` استفاده نمی‌کنند.
* **مزیت:** حذف کامل خطر Memory Fragmentation، تضمین رفتار قطعی (Deterministic Execution Time)، و امکان استفاده ایمن در وقفه‌ها (ISRs) و تسک‌های بلادرنگ (Real-Time).
* **الگوی بافر:** تمام بافرهای خروجی توسط فراخواننده (Caller) تأمین شده و ظرفیت بافر (`buffer_size`) به همراه اشاره‌گر به تابع ارسال می‌شود.

### ۱.۲. بدون وابستگی به سخت‌افزار یا لایه‌های انتزاعی (Zero Dependencies)
* کتابخانه هیچ وابستگی به STM32 HAL، CMSIS، Arduino Core یا FreeRTOS ندارد.
* با کدهای خالص C استاندارد پیاده‌سازی شده و مستقیماً روی Bare-Metal، FreeRTOS، Zephyr، ThreadX، ESP-IDF و سیستم‌عامل‌های لینوکس/ویندوز کامپایل می‌شود.

### ۱.۳. ماژولار بودن کامل (Full Modularity)
از طریق هدر پیکربندی `edc_config.h`، کاربر می‌تواند ماژول‌های غیرضروری را غیرفعال کند تا اندازه کد Flash به حداقل ممکن (کمتر از ۲ کیلوبایت) برسد.

```text
               +------------------------------------+
               |               edc.h                |
               +------------------------------------+
                                  |
     +------------+---------------+------------+------------+
     |            |               |            |            |
+----+-----+ +----+-----+   +-----+----+ +-----+----+ +-----+----+
| Numeric  | |  String  |   | Unicode  | | Persian  | |   GPS    |
| (Q/Float)| |  (Hex)   |   | (UTF8/16)| |  Arabic  | |  (NMEA)  |
+----+-----+ +----+-----+   +-----+----+ +-----+----+ +-----+----+
     |            |               |            |            |
     +------------+---------------+------------+------------+
                                  |
                   +--------------+--------------+
                   |                             |
             +-----+-----+                 +-----+-----+
             |   Units   |                 |  Parser   |
             | Converter |                 | (KV/CSV)  |
             +-----------+                 +-----------+
```

## ۲. ایمنی در برابر چندریسمانی (Thread-Safety & Stateless Design)

* **فاقد وضعیت سراسری قابل‌تغییر (Zero Global Mutable State):** کتابخانه فاقد هرگونه متغیر سراسری یا ایستا (`static/global mutable variable`) است.
* **توابع Reentrant:** تمام توابع Stateless بوده و صرفاً روی متغیرهای ورودی و پشته (Stack) محلی عمل می‌کنند؛ بنابراین به‌طور همزمان از چندین تسک FreeRTOS یا هسته‌های مختلف چندپردازنده‌ای بدون نیاز به Mutex قابل فراخوانی هستند.

## ۳. سیستم مدیریت خطا و کدهای وضعیت (Status Codes)

کتابخانه هیچ خطایی را پنهان نمی‌کند (`Never silently fail`). تمام توابع کلیدی یک مقدار بازگشتی از نوع `EDC_Status` با مقادیر زیر برمی‌گردانند:

| کد خطا | مقدار | توضیحات |
| :--- | :--- | :--- |
| `EDC_OK` | 0 | عملیات با موفقیت انجام شد. |
| `EDC_ERR_NULL_PTR` | -1 | اشاره‌گر تهی (NULL) ارسال شده است. |
| `EDC_ERR_INVALID_PARAM` | -2 | پارامتر خارج از دامنه مجاز است. |
| `EDC_ERR_BUFFER_TOO_SMALL` | -3 | بافر مقصد برای نوشتن خروجی کافی نیست. |
| `EDC_ERR_INVALID_FORMAT` | -4 | فرمت داده ورودی نامعتبر است. |
| `EDC_ERR_OVERFLOW` | -5 | سرریز عددی یا گنجایش متغیر رخ داده است. |
| `EDC_ERR_UNDERFLOW` | -6 | زیرریز عددی رخ داده است. |
| `EDC_ERR_INVALID_ENCODING`| -7 | توالی بایت‌های یونیکد یا UTF-8 غیراستاندارد است. |
| `EDC_ERR_UNSUPPORTED` | -8 | مبنا یا عمل درخواستی پشتیبانی نمی‌شود. |
| `EDC_ERR_INCOMPLETE` | -9 | جریان داده ناقص است (نیاز به بایت‌های بعدی). |
| `EDC_ERR_NOT_FOUND` | -10 | کلید یا توکن مورد نظر پیدا نشد. |
| `EDC_ERR_CHECKSUM_MISMATCH`| -11 | اعتبارسنجی جمع‌آزمایی (Checksum) با شکست مواجه شد. |

## ۴. لایه‌بندی API (Dual-Level Architecture)

کتابخانه دو لایه رابط کاربری در اختیار توسعه‌دهنده قرار می‌دهد:

1. **High-Level API:** توابع سرراست برای استفاده روزمره که تنها با ارسال بافر و متغیر، عملیات را انجام می‌دهند (مانند `EDC_Float_ToString`, `EDC_PersianDigitsToEnglish`).
2. **Low-Level API:** توابع دقیق با کنترل طول ورودی و خروجی، مبنای دلخواه، فرمت‌های نقطه‌ثابت، پردازش جریانی و اعتبارسنجی بایت به بایت (مانند `EDC_U64_ToStringEx`, `EDC_UTF8_DecodeChar`, `EDC_GPS_StreamFeed`).
